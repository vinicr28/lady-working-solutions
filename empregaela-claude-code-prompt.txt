CONTEXT
-------
You are bootstrapping a full-stack web platform called "EmpregaEla" — a job
marketplace focused on empowering women in the workforce. Companies register to
post job openings. Job seekers register to apply. The experience mirrors an
e-commerce site: browsing is public, but taking action (applying, accessing
courses) requires authentication.

Read AGENTS.md in the project root before doing anything else. It is your single
source of truth for architecture decisions, database schema, API contracts, coding
standards, and design tokens.

PHASE 2 — BACKEND (Express + TypeScript)
================================================================================

Task 2.1 — Server entry point
  - Create src/server/index.ts
  - Register middleware: cors, cookie-parser, express.json()
  - Mount all route files under /api prefix
  - Register global error middleware last
  - Listen on process.env.PORT || 3000

Task 2.2 — Auth middleware
  - Create src/server/middleware/auth.middleware.ts
  - Verify JWT from httpOnly cookie named "token"
  - Attach decoded payload to req.user
  - Export: requireAuth (throws 401 if no valid token)
  - Export: requireCompanyAuth (throws 403 if user is not a company)
  - Export: requirePersonAuth (throws 403 if user is not a person)

Task 2.3 — Auth routes (POST /api/auth/*)
  - register/person  → hash password, create Person, return JWT cookie
  - register/company → hash password, create Company, return JWT cookie
  - login            → check email+password for both Person and Company tables,
                       return JWT cookie with { id, role: "person"|"company" }
  - logout           → clear cookie
  - me               → return current user from DB (no password field)

Task 2.4 — Jobs routes
  - GET  /api/jobs          → list all active jobs, support ?search=&type=&remote=
  - GET  /api/jobs/:id      → single job with company info
  - POST /api/jobs          → requireCompanyAuth → create job
  - PUT  /api/jobs/:id      → requireCompanyAuth → update own job only
  - DELETE /api/jobs/:id    → requireCompanyAuth → soft delete (set isActive=false)

Task 2.5 — Application routes
  - POST /api/jobs/:id/apply    → requirePersonAuth → create Application
                                  (return 409 if already applied)
  - GET  /api/applications/mine → requirePersonAuth → list own applications

Task 2.6 — Courses routes
  - GET /api/courses      → requirePersonAuth → list all courses
  - GET /api/courses/:id  → requirePersonAuth → course with modules and lessons

Task 2.7 — Error middleware
  - Catch all errors, log to console in development
  - Return { success: false, error: "message" } — never expose stack traces in production

  - Routes must match the page table in AGENTS.md
  - Before rendering protected pages, check for auth token via GET /api/auth/me
  - If not authenticated on a protected route → redirect to /login with
    ?redirect= param so the user lands back after login

Task 3.3 — Pages (one TypeScript file per page)

  HOME (/):
    - Hero section: large heading "O mercado de trabalho também é seu."
    - Subheading + two CTAs: "Encontrar Vagas" and "Cadastrar Empresa"

  JOB LISTINGS (/jobs) — PUBLIC:

    - Responsive job card grid: company logo, job title, location, type badge,

    - Pagination or infinite scroll (your choice, document which)

  JOB DETAIL (/jobs/:id) — PUBLIC:
    - Full description, requirements, benefits

  APPLY (/apply/:id) — AUTH REQUIRED:

  LOGIN (/login):
